# Задача 5. Можно ли подключить существующий аккаунт ChatGPT

Ответственная: Михайлова Ангелина (Р2). Пункт ТЗ: 1, критерий приёмки 12.

## Короткий вывод для жюри

Подписка ChatGPT (Plus/Pro) и OpenAI API — разные продукты с раздельной оплатой: подписка не даёт ключа API и не даёт кредитов на API. Поэтому «просто вставить аккаунт ChatGPT в бота» нельзя, а автоматизировать веб-интерфейс chatgpt.com (скрипт, который кликает в браузере) мы не делаем: это хрупко, нарушает правила сервиса и как раз является той «незаметной подменой», которую запрещает ТЗ.

Мы нашли три честных способа и реализовали переключатель между ними. Какой механизм сейчас работает, видно в каждом ответе агента (поле `engine`) и в журнале.

| Режим | Как работает | Что даёт аккаунт ChatGPT | Ограничения |
|---|---|---|---|
| `codex` — вход через аккаунт ChatGPT | На сервере стоит Codex CLI; администратор один раз входит через `codex login --device-auth` своим аккаунтом ChatGPT. Агент вызывает `codex exec` без интерфейса. | Запросы расходуют лимиты подписки, а не оплату API по токенам | Codex рассчитан в первую очередь на задачи разработки; у подписки есть лимиты; токен входа надо обновлять. Генерации картинок в этом режиме нет — картинки идут через отдельный провайдер |
| `openai` — ключ API той же учётной записи OpenAI | Ключ с platform.openai.com, оплата по токенам | Та же учётная запись, те же модели | Отдельная оплата, подписка не засчитывается |
| ChatGPT как пульт (Apps / MCP) | Наш сервер публикуется как MCP-приложение; сотрудник в своём ChatGPT пишет «@AI-маркетолог подготовь пост». ChatGPT вызывает наши инструменты (база знаний, черновик, отправка на согласование) | Используются модель и интерфейс самого ChatGPT | Режим разработчика и свои приложения — на платных тарифах; на Business/Enterprise включает администратор рабочего пространства. Согласование и публикация всё равно идут через нашего бота. Для MVP — только в плане развития |

Плюс режимы без OpenAI для работы из РФ: `openai`-совместимые API (YandexGPT, DeepSeek через агрегатор) и `offline` для демонстрации без ключей. Модель меняется переменной окружения, база знаний и история компаний при этом не теряются (ТЗ п. 5, «Расширяемость»).

## Как выполняется проверка технической возможности

Проверка — не только текст, а запускаемый скрипт `marketer/chatgpt_check.py`. Он:
1. проверяет, что установлен Codex CLI, и пишет версию;
2. по `codex login status` определяет способ входа: аккаунт ChatGPT или API-ключ. API-ключ не засчитывается как «существующий аккаунт ChatGPT» — это оплата по токенам, и отчёт пишет это прямо;
3. отправляет реальный тестовый запрос через `codex exec` и ищет в ответе проверочное слово;
4. проверяет отсутствие подмены: при `LLM_PROVIDER=codex` без входа через ChatGPT агент явно отказывается работать с понятной ошибкой, а не переключается на другую модель;
5. сохраняет итог в `docs/chatgpt_check_result.md` (без токенов): ПОДТВЕРЖДЕНО / НЕ ПОДТВЕРЖДЕНО / НЕ ПРОВЕРЕНО с причиной.

Защита от незаметной подмены встроена в код: провайдер `codex` при старте сам вызывает `codex login status` и не запускается, если вход выполнен не аккаунтом ChatGPT. Каждый ответ агента содержит поле `engine`, а `GET /v1/engine` показывает жюри текущий движок, статус входа, доступные функции и ограничения.

Проверка запуска на машине без входа (Codex CLI 0.169.0): скрипт честно вернул «НЕ ПРОВЕРЕНО: вход в аккаунт ChatGPT не выполнен», агент с `LLM_PROVIDER=codex` отказался стартовать. Финальный результат с реальным аккаунтом получается после шагов ниже.

## Результат проверки командой (14.11.2026)

Codex CLI установлен на машине разработчика (Windows). При входе аккаунтом ChatGPT (`codex login`) OpenAI запрашивает подтверждение по номеру телефона, российские номера к подтверждению не принимаются. Обходить это (чужие или виртуальные номера) мы сознательно не стали: это нарушает правила OpenAI и создаёт риск блокировки аккаунта заказчика.

Вывод для жюри: техническая интеграция с аккаунтом ChatGPT реализована и покрыта тестами; в РФ её использование ограничено регистрацией и подтверждением аккаунта со стороны OpenAI. Если у заказчика уже есть подтверждённый аккаунт ChatGPT, он подключается командой `codex login` без изменений кода. Без входа агент в режиме `codex` явно отказывается работать и не подменяет ChatGPT другой моделью; для демо текст генерирует другая модель, и это видно в поле `engine` каждого ответа.

## Что сделать до защиты (чек-лист)

1. Собрать образ с Codex: `docker compose build --build-arg INSTALL_CODEX=true ai-agent`.
2. Войти один раз: `docker compose run --rm ai-agent codex login --device-auth`, открыть ссылку, войти аккаунтом ChatGPT, ввести одноразовый код. Токен сохранится в томе `codex_auth`.
3. `docker compose run --rm ai-agent codex login status` — должен показать вход через ChatGPT.
4. Запустить проверку: `docker compose run --rm -v ./docs:/app/docs ai-agent python -m marketer.chatgpt_check` — отчёт появится в `docs/chatgpt_check_result.md`.
5. В `.env` поставить `LLM_PROVIDER=codex`, перезапустить `ai-agent`; `GET /v1/engine` покажет `chatgpt_account: true` и статус входа.
6. Скрин для слайда: статус входа + ответ агента с полем engine. Секреты (`~/.codex/auth.json`) не показывать и не коммитить.
7. Если OpenAI недоступен из сети сервера или аккаунт не проходит по региону — фиксируем это в «Ограничениях» и показываем работу на `openai`-совместимой модели. Это тоже честный результат проверки.

## Пример конфигурации (без секретов)

```env
# Вариант A: аккаунт ChatGPT через Codex CLI
LLM_PROVIDER=codex
CODEX_BIN=codex
CODEX_MODEL=            # пусто = модель по умолчанию для тарифа

# Вариант B: ключ OpenAI API
# LLM_PROVIDER=openai
# OPENAI_API_KEY=...    # хранить в секретах сервера, не в репозитории
# OPENAI_MODEL=gpt-4o-mini

# Вариант C: YandexGPT через OpenAI-совместимый эндпоинт
# LLM_PROVIDER=openai
# OPENAI_BASE_URL=https://llm.api.cloud.yandex.net/v1
# OPENAI_API_KEY=...
# OPENAI_MODEL=gpt://<folder_id>/yandexgpt-lite/latest
```

## Как ответить на вопрос жюри «а где ChatGPT?»

«Подписка ChatGPT не открывает API — это разные продукты OpenAI. Поэтому мы подключаем аккаунт ChatGPT официальным путём через вход в Codex CLI, а для продакшена держим ключ API или российскую модель. Какой движок отвечает, видно в каждом ответе — ничего не подменяется молча.»
