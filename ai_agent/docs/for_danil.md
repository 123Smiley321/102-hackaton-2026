# AI-агент: памятка для Данила (интеграция и ответы жюри)

Короткая версия всего, что нужно, чтобы подключить агент к бэкенду и отвечать на вопросы о нём без меня.

## 1. Что это

Отдельный сервис `ai-agent` (FastAPI, Python 3.12). Хранит данные в общей PostgreSQL 16, все его таблицы начинаются с `ai_`. Backend, Telegram-бот и publication worker зовут его по `AI_AGENT_URL` с заголовком `X-Internal-Key: $AI_AGENT_API_KEY`.

Агент **никогда не публикует сам**: он возвращает текст и картинку, а согласование и публикация — у Backend и бота.

## 2. Подключение к общему compose

Агент лежит в папке `ai_agent/`, сервис `ai-agent` добавлен в корневой `docker-compose.yml`, переменные — в корневой `.env.example`. В локальный `.env` нужно дописать:

```dotenv
AI_AGENT_URL=http://ai-agent:8000/v1/generate
AI_AGENT_API_KEY=<новый независимый случайный ключ>
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://llm.api.cloud.yandex.net/v1
OPENAI_MODEL=gpt://<folder_id>/yandexgpt/latest
OPENAI_API_KEY=<ключ Yandex Cloud — передаётся лично>
IMAGE_PROVIDER=pollinations
```

Сгенерировать внутренний ключ можно так:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

`AI_AGENT_API_KEY` должен отличаться от `ADMIN_API_KEY` и `PUBLISHER_INTERNAL_KEY`. Одно и то же значение получают Backend, bot, publications и сам ai-agent; первые три передают его в `X-Internal-Key`. Пустое значение допустимо только для изолированного локального демо, для общего тестового контура включаем аутентификацию.

Порт внутри сети — 8000. Снаружи для отладки — `http://127.0.0.1:8001`, там же `/health`, `/docs` и форма `/admin`; Compose публикует порт только на loopback-интерфейсе хоста.

Yandex Cloud API key получает **только контейнер ai-agent**. Backend, bot и publications не наследуют общий `.env` целиком и не получают `OPENAI_API_KEY`. Свои VK/Telegram/admin/publisher/Fernet secrets агент также не получает.

Без ключа Яндекса агент тоже запускается (`LLM_PROVIDER=offline`): тексты собираются шаблоном из фактов базы знаний. Это план Б на случай, если Яндекс недоступен на защите. `/health` показывает фактический `engine`, поэтому offline-режим нельзя случайно выдать за YandexGPT.

## 3. Контракт

`POST http://ai-agent:8000/v1/generate` (на `/generate` и `/` тот же обработчик). Запрос — как в `generate_content` и в `monitor.draft_reply`: `prompt`, `company`, `history`, `knowledge_base`.

Ответ: обязательный непустой `text`, необязательный `image_url`. Дополнительно приходят `kind` (`draft` — пост, `answer` — ответ на вопрос, `comment_reply` — черновик ответа на комментарий), `draft_id`, `engine`, `notes`, `agent_company_id`. Лишние поля Backend игнорирует.

`image_url` — всегда публичная `https`-ссылка или `null`, потому что Backend пропускает только такие ссылки, а Telegram и VK скачивают картинку сами. Ссылка может вести на Pollinations. Если агент опубликован наружу по HTTPS, можно задать `AI_PUBLIC_MEDIA_BASE_URL`, и ссылки пойдут на сам агент. При офлайн-картинке без публичного media URL `image_url = null`, пост уходит без картинки.

Компания определяется по `company_id` (= `external_id`), если его нет — по `external_id`, затем `id`. Не-UUID строка превращается в постоянный UUID, так что одна компания Backend всегда попадает в одну изолированную базу знаний. Поля `tone_of_voice`, `target_audience`, `advantages`, `description`, `products` попадают в профиль, если компанию не настраивали через `/admin`.

Записи `knowledge_base` сохраняются в базу этой компании, повторы не задваиваются. Пустой массив — не ошибка. Backend передаёт до 20 последних knowledge items выбранной компании, `content` каждого ограничен 4000 символами.

Промпт worker-а «черновик ответа на комментарий» агент распознаёт и возвращает 1–3 вежливых предложения без поста и картинки (`kind = comment_reply`). Worker вызывает тот же `/v1/generate` с тем же `X-Internal-Key`.

Время ответа поста с картинкой — обычно 15–40 секунд (модель + самопроверка + Pollinations). У Backend таймаут чтения 90 секунд; если Pollinations перегружен, агент не ждёт бесконечно и может отдать пост без картинки.

Коды ошибок: 401 — отсутствует или неверен `X-Internal-Key`; 422 — в `company` нет ни одного id; 502 — модель недоступна.

## 4. Тесты и E2E изоляции

Автотест `tests/test_api.py::test_backend_contract_kb_isolation` проверяет две компании с разными `knowledge_base`, пустую базу, стабильный mapping company ID, comment reply, HTTPS image URL и 401 без ключа.

Запуск полного AI suite из корня репозитория после сборки образа:

```bash
docker compose run --rm --no-deps \
  -v "$PWD/ai_agent:/app" -w /app \
  --entrypoint python ai-agent -m unittest discover -s tests -v
```

Тесты используют SQLite, offline/fake LLM и offline-изображения: реальный YandexGPT для них не нужен. Отдельный живой smoke-тест с `LLM_PROVIDER=openai` обязателен перед демонстрацией.

Для проверки через Backend создать две компании, у каждой — по одной записи с уникальным словом (например, «Кристалл-7» и «раф Лаванда»), затем отправить задачу от имени второй и убедиться, что слова первой не попали ни в ответ, ни в базу второй компании. Полная генерация проверяется через Telegram-бота: `POST /api/tasks` только создаёт запись задачи и сам генерацию не запускает.

## 5. Форма настройки компании

`http://127.0.0.1:8001/admin` — форма, подключённая к агенту: профиль, загрузка PDF/DOCX/MD/TXT/HTML с типом «Факты» или «Правила и контекст», загрузка сайта, анализ бизнеса. Если задан `AI_AGENT_API_KEY`, его вводят в форме; он хранится только до закрытия вкладки.

Если вписать в форму тот же UUID, который агент вернул в `agent_company_id`, — это будет одна и та же компания. Для строкового Backend external ID сначала выполняют `/v1/generate` и используют возвращённый `agent_company_id`; не-UUID строка преобразуется детерминированно.

## 6. Частые вопросы жюри

**Какая модель?** Тексты — YandexGPT Pro через Yandex AI Studio (OpenAI-совместимый API). Картинки — Pollinations (модель FLUX). Модель меняется переменными окружения без правки кода; фактический движок виден в `/health` и в поле `engine` ответа.

**Почему не ChatGPT, ведь в ТЗ допускается существующий аккаунт?** В агенте есть режим `LLM_PROVIDER=codex`, который работает через вход в аккаунт ChatGPT и сам отказывается работать, если вход выполнен не через ChatGPT, — без скрытой подмены другим сервисом. Результат проверки записан в `docs/chatgpt_check_result.md` и `docs/chatgpt_connection.md`. Для демо выбран YandexGPT, и это видно в каждом ответе (`engine`).

**Откуда агент берёт факты?** Из базы знаний компании: документы, сайт, записи Backend. Поиск — BM25. В промпте модели запрещено писать то, чего нет во фрагментах. После генерации код проверяет пост: убирает неподтверждённые оценки и обещания, числа вне материалов и неверную атрибуцию показателей группы компаний. Если проверка что-то нашла — модель один раз переписывает пост с замечаниями.

**Как он помнит контекст?** История сообщений и решения клиента хранятся в базе по компании. Следующий пост учитывает прошлые замечания; правка создаёт новую версию черновика.

**Как не смешиваются компании?** Любой запрос к данным идёт через репозиторий с фильтром `company_id`; чужой черновик через другую компанию — 404. Это покрыто тестами.

**Что будет после перезапуска?** Профили, документы, история и черновики остаются в PostgreSQL; медиа — в volume `ai_media`. Тест `test_state_after_restart` проверяет сохранение состояния.

**Ограничения (честно).** Поиск по словам, без векторной модели. Таблицы создаются при старте, миграций Alembic нет. Картинки отдаются по неугадываемому адресу без авторизации. Pollinations иногда отвечает медленно; в этом случае допустим `image_url=null`, но критерий генерации изображения нужно проверить отдельным успешным прогоном.

## 7. Где что лежит

- `marketer/api.py` — HTTP API; `marketer/agent.py` — логика агента; `marketer/checks.py` — автопроверка поста; `marketer/prompts/*_v3.md` — промпт-контракт.
- `demo_data/salavatsteklo/` — демонстрационный пакет и профиль компании; `demo.py` — отдельный сценарий агента.
- Корневой `README.md` и `Кибер102_Докер_инструкция.md` у Данила — запуск всего пятисервисного контура и сквозной Telegram → AI → approval → worker → publish E2E.
