# AI-агент: памятка для Данила (интеграция и ответы жюри)

Короткая версия всего, что нужно, чтобы подключить агент к бэкенду и отвечать на вопросы о нём без меня.

## 1. Что это

Отдельный сервис `ai-agent` (FastAPI, Python 3.12). Хранит данные в общей PostgreSQL 16, все его таблицы начинаются с `ai_`. Бэкенд зовёт его по `AI_AGENT_URL` с заголовком `X-Internal-Key: $AI_AGENT_API_KEY`.

Агент **никогда не публикует сам**: он возвращает текст и картинку, а согласование и публикация — у бэкенда и бота.

## 2. Подключение к общему compose

Уже сделано в ветке `ai-agent`: агент лежит в папке `ai_agent/`, сервис `ai-agent` добавлен в корневой `docker-compose.yml`, переменные — в корневой `.env.example`. В свой `.env` нужно дописать:

```
AI_AGENT_URL=http://ai-agent:8000/v1/generate
LLM_PROVIDER=openai
OPENAI_BASE_URL=https://llm.api.cloud.yandex.net/v1
OPENAI_MODEL=gpt://<folder_id>/yandexgpt/latest
OPENAI_API_KEY=<ключ Yandex Cloud — передаю лично>
IMAGE_PROVIDER=pollinations
```

Порт внутри сети — 8000 (не 8001, как в комментарии `backend/app/config.py`). Снаружи для отладки — `http://localhost:8001`, там же `/health`, `/docs` и форма `/admin`.

`AI_AGENT_API_KEY` оставить пустым: бэкенд и воркер сейчас не отправляют заголовок `X-Internal-Key`. Агент доступен только из сети Docker и с локальной машины.

Без ключа Яндекса агент тоже запускается (`LLM_PROVIDER=offline`): тексты собираются шаблоном из фактов базы знаний. Это план Б на случай, если Яндекс недоступен на защите.

## 3. Контракт

`POST http://ai-agent:8000/v1/generate` (на `/generate` и `/` тот же обработчик). Запрос — как в `generate_content` и в `monitor.draft_reply`: `prompt`, `company`, `history`, `knowledge_base`.

Ответ: обязательный непустой `text`, необязательный `image_url`. Дополнительно приходят `kind` (`draft` — пост, `answer` — ответ на вопрос, `comment_reply` — черновик ответа на комментарий), `draft_id`, `engine`, `notes`, `agent_company_id`. Лишние поля бэкенд игнорирует.

`image_url` — всегда публичная `https`-ссылка или `null`, потому что `_validate_image_url` пропускает только такие, а Telegram и VK скачивают картинку сами. Ссылка ведёт на Pollinations (та же картинка, фиксированный seed). Если агент когда-нибудь опубликуют наружу по https, можно задать `AI_PUBLIC_MEDIA_BASE_URL`, и ссылки пойдут на сам агент. При офлайн-картинке `image_url = null`, пост уходит без картинки.

Компания определяется по `company_id` (= `external_id`), если его нет — по `id`. Не-UUID строка превращается в постоянный UUID, так что одна компания бэкенда всегда попадает в одну изолированную базу знаний. Поля `tone_of_voice`, `target_audience`, `advantages`, `description`, `products` попадают в профиль, если компанию не настраивали через `/admin`.

Записи `knowledge_base` сохраняются в базу этой компании, повторы не задваиваются. Пустой массив — не ошибка.

Промпт воркера «черновик ответа на комментарий» агент распознаёт и возвращает 1–3 вежливых предложения без поста и картинки (`kind = comment_reply`).

Время ответа: пост с картинкой — обычно 15–40 секунд (модель + самопроверка + Pollinations). У бэкенда таймаут чтения 90 секунд, этого хватает; если Pollinations перегружен, агент не ждёт бесконечно и отдаёт пост без картинки.

Коды ошибок: 422 — в `company` нет ни одного id, 502 — модель недоступна.

## 4. E2E «знания двух компаний не смешиваются»

Уже есть автотест `tests/test_api.py::test_backend_contract_kb_isolation`: две компании с разными `knowledge_base`, пост и вопрос для каждой, проверка, что факты одной не попадают в ответ другой, что пустая база не роняет агент и что без ключа — 401. Запуск: `python -m unittest discover -s tests -v`.

Для проверки уже через бэкенд: создать две компании, у каждой — по одной записи с уникальным словом (например, «Кристалл-7» и «раф Лаванда»), попросить пост от имени второй и убедиться, что слова первой в ответе нет.

## 5. Форма настройки компании

`http://localhost:8001/admin` — форма Лизы, подключённая к агенту: профиль, загрузка PDF/DOCX/MD/TXT/HTML с типом «Факты» или «Правила и контекст», загрузка сайта, анализ бизнеса. Закрывает критерий 11 «настройка без кода». Если вписать в форму тот же `company_id`, что у компании в бэкенде (в виде UUID), — это будет одна и та же компания.

## 6. Частые вопросы жюри

**Какая модель?** Тексты — YandexGPT Pro через Yandex AI Studio (OpenAI-совместимый API). Картинки — Pollinations (модель FLUX), бесплатно и без ключа. Модель меняется переменными окружения без правки кода; текущая видна в `/health`.

**Почему не ChatGPT, ведь в ТЗ допускается существующий аккаунт?** Мы это проверили: в агенте есть режим `LLM_PROVIDER=codex`, который работает через вход в аккаунт ChatGPT и сам отказывается работать, если вход выполнен не через ChatGPT, — без скрытой подмены другим сервисом. Вход у нас упёрся в обязательное подтверждение номером телефона, российский номер не принимается. Результат проверки записан в `docs/chatgpt_check_result.md` и `docs/chatgpt_connection.md`. Поэтому для демо — YandexGPT, и это видно в каждом ответе (`engine`).

**Откуда агент берёт факты? Не выдумывает ли?** Только из базы знаний компании: документы, сайт, записи бэкенда. Поиск — BM25 (по словам). В промпте модели запрещено писать то, чего нет во фрагментах. После генерации код проверяет пост: убирает оценки и обещания («высокое качество», «лидер», «надёжный»), числа, которых нет в материалах, неверную атрибуцию (показатели группы компаний — не показатели АО). Если проверка что-то нашла — модель один раз переписывает пост с замечаниями. На вопрос «на какие сведения опираешься?» агент перечисляет факты с документом и ссылкой на официальный источник.

**Как он помнит контекст?** История сообщений и решения клиента («всегда добавляй ссылку на каталог») хранятся в базе по компании. Следующий пост учитывает прошлые замечания, правка «сделай короче» создаёт версию 2 того же черновика.

**Как не смешиваются компании?** Любой запрос к данным идёт через репозиторий с фильтром `company_id`; чужой черновик через другую компанию — 404. Это покрыто тестами.

**Что будет после перезапуска?** Всё в PostgreSQL: профили, документы, история, черновики. Тест `test_state_after_restart` это проверяет.

**Сколько стоит?** Картинки — бесплатно. YandexGPT Pro — оплата по токенам, один пост — копейки; на хакатон хватило пополнения на 200 ₽.

**Ограничения (честно).** Поиск по словам, без векторной модели. Таблицы создаются при старте, миграций Alembic нет. Картинки отдаются по неугадываемому адресу без авторизации. Pollinations ставит небольшой водяной знак и иногда отвечает медленно (агент повторяет запрос сам).
