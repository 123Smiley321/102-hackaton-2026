# Проверки задачи №16 — согласование публикаций

## Подготовка

1. Применить `migration_task16_approval_workflow.sql` к существующей PostgreSQL БД.
2. У компании задать `approval_chat_id` (или `telegram_chat_id`), `enabled_platforms`, `approval_required=true`.
3. Запустить Backend и Telegram bot; убедиться, что AI-agent доступен.

## Сценарии

1. **Создание согласования:** отправить поручение боту. В чате согласования должны прийти отдельные сообщения для каждой включённой площадки. В сообщении видны компания, площадка, время, версия и материал.
2. **Одобрение:** нажать «Одобрить». Статус соответствующей площадки становится `approved`; появляется запись аудита. Воркер может забрать только эту запись.
3. **Отклонение:** нажать «Отклонить». Статус становится `rejected`; запись не должна попасть в очередь публикаций.
4. **Доработка:** нажать «Доработать», ответить на ForceReply-комментарий. Backend передаёт исходный текст и комментарий AI-agent, сохраняет новую версию, увеличивает `approval_version`, очищает `approved_by/approved_at` и повторно отправляет материал на согласование.
5. **Повторное согласование:** до нового нажатия «Одобрить» статус должен быть `pending_approval`, а публикационный воркер не должен отправлять материал. После нового одобрения статус становится `approved`.
6. **Неверный чат:** попытка нажать кнопку из другого чата должна быть отклонена.
7. **Двойное нажатие:** повторное нажатие после смены статуса не должно создавать повторное одобрение.
8. **Режим per_platform:** одобрение VK не должно автоматически одобрять Telegram и наоборот.
9. **Режим all_platforms:** отдельные одобрения получают статус `approved_waiting`; только после одобрения всех площадок все записи переводятся в `approved`.
10. **Время:** если `scheduled_at` задан, оно отображается в уведомлении; если нет — отображается «Сразу после одобрения».

## Автоматические проверки

- `python -m compileall -q app`
- Проверить в БД, что публикационный воркер выбирает только `status='approved'`.
