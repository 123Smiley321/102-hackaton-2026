# Проверка задачи №12 — Telegram-бот и история диалога

## Подготовка

1. Создать `.env` из `.env.example`.
2. Заполнить `TELEGRAM_BOT_TOKEN` и `AI_AGENT_URL`.
3. Запустить БД и Backend: `docker compose up --build -d db backend`.
4. Запустить отдельный процесс Telegram-бота: `docker compose --profile telegram up --build -d bot`.
5. Создать профиль компании через `POST /api/companies`, указав `telegram_chat_id`.

## Приёмочные проверки

- [ ] `/start` показывает статус подключения; для непривязанного чата сообщает chat_id.
- [ ] Свободное текстовое поручение создаёт запись `tasks` и сохраняет сообщение пользователя в `message_history`.
- [ ] В запрос AI-agent передаются `company` и до 12 последних сообщений `history` текущей компании и текущего чата.
- [ ] Ответ AI сохраняется в `message_history` с ролью `assistant`.
- [ ] При успешной генерации создаётся черновик и бот сообщает, что он отправлен на согласование.
- [ ] `/history` показывает до 10 последних сообщений текущего чата.
- [ ] При недоступности AI-agent задача получает статус `error`, в истории появляется запись об ошибке, пользователь получает уведомление.
- [ ] История двух разных компаний/чатов не смешивается.
- [ ] После перезапуска контейнера ранее сохранённая история доступна через `/history`.

## Контракт backend → AI-agent

Запрос: `POST AI_AGENT_URL`

```json
{
  "prompt": "Подготовь пост о продукте",
  "company": {
    "id": 1,
    "name": "Тестовая компания",
    "description": "...",
    "tone_of_voice": "...",
    "products": "...",
    "target_audience": "...",
    "advantages": "..."
  },
  "history": [
    {"role": "user", "content": "Первое поручение"},
    {"role": "assistant", "content": "Предыдущий ответ"}
  ]
}
```

Ответ: `{"text": "Текст черновика", "image_url": "https://..."}`. `image_url` необязателен.

> Задача №12 не заменяет задачи №16–17: текущие callback-обработчики согласования и прямой VK-публикации остаются временными и должны быть переведены на контракт с модулем публикаций отдельно.


## Интеграция с модулем публикаций (обновление)

- [ ] Нажатие «Одобрить» переводит только запись со статусом `pending_approval` в `approved`.
- [ ] При согласовании заполняются `approved_by` и `approved_at` (UTC).
- [ ] Обработчик бота не вызывает VK API и не меняет статус на `publishing`/`published`.
- [ ] Повторное нажатие не создаёт повторную задачу: запись с любым статусом, кроме `pending_approval`, повторно не одобряется.
- [ ] Воркер публикаций забирает `approved`-строки с блокировкой `FOR UPDATE SKIP LOCKED` и самостоятельно управляет статусами доставки.
- [ ] Для каждой площадки создана отдельная строка `publications` с уникальным `idempotency_key`.


## Сопоставление идентификатора компании
- [ ] Создать компанию с `company_id: "salavatsteklo_demo"`.
- [ ] Проверить, что ответ содержит числовой `id` и строковый `company_id`/`external_id`.
- [ ] Повторное создание с тем же `company_id` возвращает HTTP 409.
- [ ] AI-agent получает `company.company_id = "salavatsteklo_demo"`, а `company.id` остаётся внутренним числом.
- [ ] Найти компанию через `/api/companies/by-external-id/salavatsteklo_demo`.
